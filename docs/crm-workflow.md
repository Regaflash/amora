# CRM Workflow — מהקליק על המודעה ועד חוזה חתום

המערכת: קליטת לידים משלושה ערוצים → CRM אחד (`admin.html`) → פייפליין מכירה →
חוזה ממותג שנחתם מהנייד. הכול על התשתית הקיימת — Supabase + הדף הסטטי — בלי
תלות חדשה ובלי לשבור את כללי האתר.

```
Google Ads ──webhook──► lead-intake-google ─┐
Meta Lead Ads ─poller (Windsor)─────────────┤──► public.leads ──trigger──► lead-alert (מייל)
האתר (הטופס) ──anon INSERT──────────────────┘        │
                                                     ▼
                                          admin.html (ה-CRM)
                                  חדש → נוצר קשר → הצעה → חוזה נשלח → נחתם
                                                     │
                                        contracts + דף חתימה ממותג
                                        (functions/v1/contract?t=…)
```

המצבים), אבל אין סטטוסים, אין חוזים ואין קליטת מודעות. המיגרציה היא הצעד
הפותח של הכול.

## ערוצי הקליטה

### 1. האתר — עובד היום, ללא שינוי

הטופס כותב `INSERT` עם מפתח anon אל `public.leads`. אחרי המיגרציה ההרשאה
הופכת column-scoped (עשר עמודות הטופס בלבד) — זר עם המפתח הציבורי לא יכול
לקבוע `status`, `campaign` או `external_id`.

### 2. Google Ads — webhook מובנה, בלי חיבור חשבון

לטפסי הלידים של Google Ads יש מסירת webhook מובנית. ההגדרה (בעלים, ~2 דקות):

1. להריץ את המיגרציה (נולד בה מפתח סודי).
2. לשלוף את המפתח: `select value from private.settings where key = 'google_lead_webhook_key';`
3. ב-Google Ads → Assets → Lead form → Lead delivery → Webhook:
   - URL: `https://dkejuaildigikufrdiru.supabase.co/functions/v1/lead-intake-google`
   - Key: הערך מסעיף 2.
4. ללחוץ **Send test data** — ליד בדיקה (מסומן `[בדיקת מערכת]`) חייב להופיע
   ב-`admin.html` תוך שניות.

הפונקציה מאמתת את המפתח, ממפה `FULL_NAME/PHONE_NUMBER/EMAIL`, דוחסת שאלות
מותאמות אל `message`, וכותבת `source='google-ads'` + `external_id` ייחודי
(כפילויות מ-retry של גוגל נבלעות). ליד בלי טלפון נדחה ב-422 בכוונה — שגיאת
תצורה צריכה להיראות בדשבורד של גוגל, לא להיבלע.

### 3. Meta Lead Ads — פולר דרך חיבור Windsor

חשבון ה-Meta של הסטודיו כבר מחובר ל-Windsor.ai (קונקטור `facebook_leads`,
עמוד "Amora Studio - צילומי וידאו וסטילס", id `735764282962651`). נכון להיום
יש שם **~90 לידים אמיתיים מ-90 הימים האחרונים** — חתונות ובר/בת מצווה — שלא
נקלטו בשום מקום.

רוטינת Claude שעתית **"Amora — Meta leads poller"** כבר קיימת ורצה בראש כל
שעה. עד שהמיגרציה תרוץ היא בודקת אם `leads.external_id` קיים ויוצאת בשקט —
בלי הודעות ובלי כתיבה. בריצה הראשונה אחרי המיגרציה היא מייבאת את כל 89 הימים
אחורה (≈90 הלידים הקיימים), ומשם ואילך שלושה ימים אחורה בכל ריצה. היא מושכת
וכותבת רק שורות חדשות:

- `external_id = 'meta:' + <lead id>` — הכפילות נחסמת באינדקס הייחודי.
- `source = 'meta-ads'`, `campaign = <שם הקמפיין>`.
- `name` ← fullname, `phone` ← phone, `email` ← email/דוא"ל.
- תשובות נוספות (תאריך חתונה, עיר, "מתי נוח שנתקשר") ← `message`.
- `event_type` לפי הטופס: `2411683559263058` = חתונות, `2466279637158619` =
  בר/בת מצווה.

מגבלה ידועה: לידים ב-Meta נשמרים 90 יום אחורה בלבד, והפולר רץ פעם בשעה —
ליד מגיע ל-CRM באיחור של עד שעה. שדרוג עתידי: webhook אמיתי של Meta (דורש
אפליקציית Meta מאושרת). ההתראה במייל נורית מה-trigger הקיים על INSERT, כמו
בכל ערוץ אחר.

## הפייפליין ב-CRM

סטטוסים: **חדש → נוצר קשר → הצעה נשלחה → חוזה נשלח → נחתם ✓ / לא נסגר**.
שינוי סטטוס מסנכרן את דגל `handled` הישן (הכול חוץ מ"חדש" = טופל), כך
שהצ'יפים "ממתינות/טופלו" ממשיכים לעבוד. לכל כרטיס נוספו: תג ערוץ
(האתר / Google Ads / Meta), שורת קמפיין, ופתק חופשי. כל פעולה נרשמת גם
ל-`lead_events` (best-effort — ציר זמן, לא מנגנון).

## החוזה — מהכרטיס ועד חתימה

1. **יצירה** — כפתור "יצירת חוזה" בכרטיס פותח טופס (שם, תאריך, אולם, חבילה,
   מחיר, מקדמה). המחיר חי בחוזה בלבד — כלל ה"בלי מחירים" חל על האתר הציבורי,
   לא על המסמכים של הסטודיו. נוצרת שורה ב-`contracts` עם token אקראי
   (48 hex) שהוא כל ההרשאה.
2. **שליחה** — "שליחה בוואטסאפ" פותח שיחה עם הודעה מנוסחת + קישור החתימה.
   "סימון כנשלח" מעדכן את החוזה והליד. אין תלות במייל.
3. **חתימה** — הזוג פותח דף ממותג (RTL, פלטת האתר, הלוגו), קורא, חותם עם
   האצבע על canvas, מאשר וחותם. נשמרים: החתימה (PNG), שם, מועד, IP,
   user-agent. הליד קופץ ל"נחתם ✓" אוטומטית, וכשה-Resend מוגדר — אישור נשלח
   במייל לשני הצדדים. הדף החתום נשאר זמין באותו קישור, עם הדפסה/שמירה כ-PDF.
4. **צפייה ב-CRM** — הכרטיס מציג את מצב החוזה חי: טיוטה / נשלח (+נצפה) /
   נחתם ✓ עם תאריך.

נוסח הסעיפים הוא **טיוטה** עם באנר גלוי וסימוני `[להשלים]` — אותה קונבנציה
כמו `privacy.html` ו-`terms.html`, ואותו חסם: עורך דין של הבעלים. סעיפי
האספקה מוצמדים להבטחות האתר (7 ימים / 30 יום / שבועיים מאישור / סרט 3–5
דקות) — חוזה לא מבטיח פחות ממה שדף הבית מבטיח.

## צ'קליסט הפעלה — לפי סדר

1. **[בעלים] המיגרציה** — להריץ את `docs/supabase-crm-pipeline.sql` ב-SQL
   Editor (או לאשר ל-Claude כתיבת DB). בלי זה שום דבר חדש לא פעיל.
2. **[בעלים] merge + deploy** — הענף הזה ל-main; Vercel יפרוס את ה-CRM המשודרג.
3. **[בעלים] Google Ads** — להדביק URL + מפתח (ראו ערוץ 2) ולשלוח test data.
4. **[אוטומטי] פולר Meta** — אין מה לעשות: הרוטינה השעתית תזהה שהמיגרציה רצה
   ותייבא בריצה הבאה את ~90 הלידים הקיימים, ואז תמשיך שוטף.
5. **[בעלים] Resend** — `RESEND_API_KEY` + `LEAD_ALERT_TO` (צעד שכבר ממתין
   ב-`docs/lead-alerts.md`); מפעיל גם התראות ליד וגם אישורי חוזה.
6. **[בעלים] עו"ד** — נוסח החוזה + פרטי העסק ב-`CONTRACT_STUDIO`
   (ב-`supabase/functions/contract/index.ts`) ופריסה מחדש של הפונקציה.

## אימות אחרי כל צעד

- מיגרציה: בלוק ה-verify בסוף `docs/supabase-crm-pipeline.sql`.
- Google: ליד `[בדיקת מערכת]` ב-CRM + `lead-intake-google: inserted` בלוגים.
- Meta: אחרי הריצה הראשונה — `select count(*) from public.leads where source='meta-ads';`

  שהכרטיס קפץ ל"נחתם ✓" — ואז לבטל אותו (סטטוס cancelled) כדי שלא יבלבל.
