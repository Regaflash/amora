# תרגום האתר — ה-FLOW של התהליך

כפתור שפה ליד התפריט (עברית · English · Русский · العربية). לחיצה מתרגמת את
**העמוד שהמבקר נמצא בו בלבד**, המעבר לעמוד הבא מתרגם אותו מיד, וכל מחרוזת
שתורגמה פעם אחת נשמרת ב-Supabase — כך שהמבקר הבא מקבל אותה מיידית בלי קריאה
למודל.

---

## למה בכלל

הפילוח באתר היום הוא עברית בלבד. בישראל שוק החתונות כולל דוברי רוסית וערבית
בהיקף משמעותי, ותיירות חתונות מגיעה באנגלית. עלות התרגום נופלת כמעט לאפס אחרי
המבקר הראשון — זו בדיוק צורת הבעיה שמטמון פותר.

## מה כבר קיים ובודק את עצמו

| רכיב | מצב |
| --- | --- |
| `connect-src` ב-CSP | **כבר מכסה** את `dkejuaildigikufrdiru.supabase.co` — אפס שינוי |
| מפתחות מודל | `GEMINI_API_KEY`, `CEREBRAS_API_KEY`, `NVIDIA_API_KEY` — מוגדרים |
| Edge Functions | תשתית פרוסה ועובדת (`lead-alert` אומת 200 ב-4.8) |
| היקף טקסט | `index` 185 מחרוזות / 4.4KB · `cost` 104 / 2.9KB · `camera-3d` 33 / 0.5KB |

עמוד שלם נכנס בקריאה אחת למודל. אין כאן בעיית קנה מידה.

## ה-FLOW בזמן ריצה

```
המבקר לוחץ "Русский"
        │
        ▼
1. הלקוח סורק את ה-DOM
   ├─ צמתי טקסט גלויים
   ├─ alt / title / placeholder / aria-label
   └─ מדלג על: script, style, JSON-LD, [data-no-translate]
        │
        ▼
2. נרמול + גיבוב            trim + כיווץ רווחים → sha256
   "  שלום  " ו-"שלום" = אותו מפתח מטמון
        │
        ▼
3. POST /functions/v1/translate   { lang:"ru", items:[{h,s},…] }
        │
        ▼
4. הפונקציה בודקת את public.translations לפי (hash, lang)
        │
        ├── פגיעות מטמון ─────────────► מוחזרות מיד
        │
        └── החטאות ──► קריאה אחת למודל (Gemini ראשי)
                        ├─ הצליח → INSERT למטמון → מוחזר
                        └─ נכשל  → Cerebras → NVIDIA → ויתור
        │
        ▼
5. הלקוח מחיל על ה-DOM, מעדכן <html lang> ו-dir
        │
        ▼
6. localStorage: amora.lang = "ru"
        │
        ▼
7. עמוד הבא → שלב 1 רץ אוטומטית. עכשיו רוב המחרוזות
   כבר במטמון (ניווט, פוטר, כפתורים חוזרים בכל עמוד)
```

**המבקר הראשון** משלם קריאה אחת למודל לעמוד. **כל השאר** מקבלים DB lookup.
המחרוזות המשותפות (ניווט, פוטר, "בדיקת זמינות") מתחממות אחרי העמוד הראשון —
לכן המטמון ממופתח לפי **מחרוזת, לא לפי עמוד**.

## מודל הנתונים

```sql
create table public.translations (
  hash       text not null,                    -- sha256 של המקור המנורמל
  lang       text not null check (lang in ('en','ru','ar')),
  source     text not null,
  target     text not null,
  model      text,                             -- מי תרגם, לצורך ביקורת איכות
  created_at timestamptz not null default now(),
  primary key (hash, lang)
);
```

הרשאות לפי אותה פילוסופיה של `docs/supabase-crm.sql`: **`anon` לא ניגש לטבלה
כלל.** כל קריאה וכתיבה עוברות דרך הפונקציה עם service role. זה לא בגלל
סודיות — זה טקסט שיווקי פומבי — אלא כדי לשמור על שטח תקיפה קטן ועל מקור אמת
אחד לכתיבה.

## שלוש החלטות שצריך לקבל לפני קוד

### 1. אנגלית ורוסית ישברו את הפריסה. ערבית לא.

נמדד: `assets/css/styles.css` מכיל **34 מאפיינים פיזיים**
(`left`, `right`, `border-left/right`, `text-align: right`) מול **7 לוגיים**.

- **ערבית** — RTL, אותו כיוון כמו עברית. **drop-in, אפס סיכון פריסה.**
- **אנגלית / רוסית** — LTR. החלפת `dir` תחשוף כל אחד מ-34 המקומות.

`CLAUDE.md` כבר מתעד ש"מאפיינים פיזיים הם מקור באגים חוזר" באתר הזה. לכן
**ערבית משוחררת ראשונה**, ו-EN/RU רק אחרי מעבר CSS מדוד.

### 2. עמודי המשפט לא מתורגמים במכונה

`privacy.html`, `terms.html` ו-`accessibility.html` הם **טיוטות** עם 28 סימוני
`[להשלים]` וממתינים לעורך דין. תרגום מכונה שלהם מייצר מסמך משפטי שהסטודיו לא
כתב, לא קרא, ולא יכול לעמוד מאחוריו — בשפה שהבעלים אולי לא קורא.

זו אותה הפרה שבגללה ירדו תמונות הממליצים: תוכן שנראה אותנטי ואינו.

**במקום:** בעמודים האלה הכפתור מציג שורה בשפת היעד — "מסמך זה מחייב בעברית
בלבד" — עם קישור חזרה. אחרי שעו"ד יאשר נוסח, אפשר לתרגם **בתרגום אנושי**.

### 3. ה-SEO לא נפגע — ובלבד שלא ניצור כתובות

התרגום מתרחש **בדפדפן בלבד**. גוגל ממשיך לראות עברית, שהיא הקנוני. אין
`/en/`, אין `/ru/`, אין `hreflang`. זה מכוון: עמודי שפה שנוצרים ממכונה על אותו
תוכן הם בדיוק דפוס ה-doorway ש-`CLAUDE.md` כבר החליט להימנע ממנו. ה-JSON-LD
נשאר עברית.

## עלות והגנות

- **תקרה לכל בקשה:** 200 מחרוזות / 12KB. עמוד גדול יותר נחתך ומדווח בלוג.
- **הגבלת קצב:** לפי IP בפונקציה. תוקף לא יכול לשרוף מכסת מודל בלולאה.
- **כשל שקוף:** אם כל שלושת המודלים נופלים, העמוד **נשאר עברית**. אין מצב
  שבור, אין טקסט חסר — בדיוק כמו נפילת טופס הלידים שנופלת לוואטסאפ.
- **`he` תמיד זמין** — לחיצה על "עברית" מסירה את התרגום בלי קריאת רשת.

## התקלה של 5.8 — מתג השפה היה מת לכל מבקר

**מה קרה.** כל `POST` ל-`translate` החזיר **500**. `OPTIONS` החזיר 200 לאורך
כל הזמן — כלומר המודול עלה תקין ונפל על העבודה האמיתית הראשונה.

**מה גרם.** קריאת המטמון בנתה `hash=in.(...)` אחד עם **כל** ההאשים של העמוד.
דף שלם מגיע בקריאה אחת, ו-240 האשים באורך 64 תווים הם כתובת של ~16KB. זה
מעבר למה ששער הכניסה שלפני PostgREST נושא, ובקשה שנדחית שם אינה חוזרת כקוד
סטטוס — ה-`fetch` **זורק**. זו הייתה ה-`fetch` היחידה בנתיב הבקשה שלא הייתה
עטופה, וזריקה לא מטופלת בתוך המטפל היא 500.

**איך זה עבר את הפיתוח.** הבדיקות בזמן הבנייה שלחו שלושה מחרוזות. שלוש עובדות,
240 לא — וזה בדיוק ההבדל בין בדיקה למבקר.

### המדידה, כי בלעדיה זו הייתה השערה

מסביבת הבנייה אין רשת אל Supabase (הפרוקסי מחזיר 403), אז הקריאה נעשתה
**מתוך מסד הנתונים** ב-`pg_net` — מה שגם מוכיח שיש דרך לבדוק Edge Function
בלי דפדפן ובלי מסוף:

```sql
select net.http_post(
  url := 'https://<ref>.supabase.co/functions/v1/translate',
  headers := '{"content-type":"application/json"}'::jsonb,
  body := jsonb_build_object('lang','en','items', <240 פריטים>),
  timeout_milliseconds := 30000
);
-- ואז:
select status_code, content from net._http_response where id = <id>;
```

| מה נשלח | גרסה 5 | גרסה 6 |
|---|---|---|
| 240 פריטים | **500** `Internal Server Error` | **200**, `cached: 240, fresh: 0` |
| 3 פריטים (מטמון חם) | 200, נכון | 200, נכון |

הבדיקה של 240 נעשתה על 240 שורות מטמון שנזרעו מראש ונמחקו אחריה, כדי שהנתיב
היחיד שנמדד יהיה קריאת המטמון — בלי קריאת מודל שתטשטש את התוצאה ובלי לזהם את
`public.translations`. הטבלה חזרה לשלוש השורות שהיו בה.

### התיקון, ולמה שני חצאים

`CHUNK = 30` — כתובת של ~2KB, הרחק מכל מגבלת שורת-בקשה — והקטעים רצים
במקביל ב-`Promise.all`. **וכל קטע בתוך `try`.** אם זה ייכשל שוב מסיבה שאיש
לא צפה, המבקר מקבל עמוד מתורגם על ידי המודל במקום שגיאה, והסיבה חוזרת בשדה
`note` במקום למות בלוג.

**קריאת מטמון היא אופטימיזציה, ואופטימיזציה לא אמורה להיות מסוגלת להפיל את
הבקשה.** זו השורה שאם היא הייתה כתובה בקוד מלכתחילה, התקלה הזאת לא הייתה
קיימת.

### מה עדיין לא נמדד

**כמה זמן לוקח עמוד שלם עם מטמון קר.** ניסיון עם 240 מחרוזות טריות לא חזר
תוך 60 שניות ו-`pg_net` ויתר. הן היו 240 עותקים של אותה מילה — קלט מוזר
שאי אפשר להסיק ממנו על עמוד אמיתי — אבל גם אי אפשר להכריז שהמעבר מהיר. המבקר
הראשון בכל שפה משלם את המחיר הזה; השני כבר קורא מהמטמון. אם יתברר שזה איטי,
הפתרון הוא לחלק גם את קריאת המודל, ולא להגדיל את התקרה.
