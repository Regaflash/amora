# Amora Studio

אתר תדמית לסטודיו צילום וידאו וסטילס לחתונות ואירועים — תל אביב.
Static site, RTL Hebrew, no build step and no dependencies.

Implemented from the Claude Design handoff bundle in [`project/`](project/) —
see [`docs/handoff.md`](docs/handoff.md) for the original brief and
[`chats/`](chats/) for the design conversation.

## Running it

Any static file server will do — the pages use relative paths only:

```bash
python3 -m http.server 8000
# → http://localhost:8000
```

Opening `index.html` straight off the filesystem mostly works, but the `#gear`
section's `<iframe>` and the three.js module imports need `http://`.

## Media

The photography is wired in — 27 `<picture>` elements, WebP with JPEG fallback,
two widths each, `srcset` + `sizes`, lazy-loaded below the fold. Source images
came from the studio's own library (78 unique frames after de-duplication).

Derivatives live in `assets/img/` and are generated, not hand-made. Slot → source

### The hero

The studio's own footage, streamed from YouTube. Two cuts, picked by the
viewport's orientation so neither is a centre-crop of the other: the showreel
(`2DHdORDXVmo`) on landscape screens, the vertical Short (`3O13FGO_f08`) on a
phone held upright. `initHero` in `main.js` builds the iframe and re-picks if
the viewport crosses the boundary; there is no `<video>` element and no
`assets/video/`.

| | |
| --- | --- |
| `hero-wide-poster.jpg / .webp` | 1280×720 — the hero still, and what stands alone whenever the embed does not play |
| `hero-vertical-poster.jpg / .webp` | art-directed portrait cut of the same |

Nothing is fetched from Google when `prefers-reduced-motion` is set, when
`navigator.connection.saveData` is on, or on a 2g connection — the poster is a
complete hero on its own. The frame also has to prove it is alive over
`postMessage` within 12s or it is removed. It pauses when the tab is hidden or
the hero scrolls out of view.

This is the one third-party request the site makes on load, and it was the
owner's call with the trade-off on the table. `privacy.html` says so in as many
words, and `frame-src` in `vercel.json` names the two origins the embed may
speak from. The film section further down still asks before it loads. **Keep
all three in step if the hero ever changes back.**

Text legibility over the hero is measured, not eyeballed: worst-case contrast
across every frame is 6.5:1 (desktop) and 5.5:1 (mobile) against `#FFFDF9`.
The `.hero__scrim` ellipse is what buys that — with the design's original
linear wash alone it was 2.2:1, and the headline disappeared into the veil.
If you swap in a brighter source, re-check it.

Wide slots (16:9, 21:9) were filled from square sources cropped horizontally —
the library had exactly one landscape frame. Scenes were chosen so the crop
works (venue, dance floor, table settings) rather than cropping portraits.

## The lead form

Collects name, phone, date, event type, area and coverage, plus a honeypot.
Validates client-side, then:

- **With `CONFIG.formEndpoint` set** — POSTs JSON with a 12s timeout. A failure
  shows a real error and offers the same details over WhatsApp, so a network
  blip never loses a lead.
- **With it empty (the default)** — hands the completed details to WhatsApp as
  a formatted message. It does **not** show a thank-you for a message that was
  never sent. The site never tells a visitor it received something it didn't.

It posts to Supabase — `CONFIG.supabaseUrl` / `supabaseKey` at the top of
`assets/js/main.js`, table `leads`, created by `docs/supabase-leads.sql`. The
anon key is public by design; the RLS policy allows INSERT and nothing else.
`CONFIG.formEndpoint` is still there as a fallback for any generic form
service, and with neither configured the form hands the details to WhatsApp
rather than claim a delivery it cannot confirm.

`admin.html` reads those leads back. It is a private tool: `noindex`,
`no-store`, its own enforcing CSP, and it signs in as a real Supabase user
whose membership of `public.admins` is what the policies in
`docs/supabase-crm.sql` actually test. It is deliberately absent from
`sitemap.xml` and from `robots.txt` so its path is not advertised.

## Before going live

```bash
tools/set-site-url.sh https://your-domain.co.il   # fills the SITE_URL placeholder
tools/check.sh                                    # 14 checks; must exit 0
```

`.vercelignore` decides what ships: the six HTML pages, `favicon.ico`,
`robots.txt`, `sitemap.xml` and `assets/`. `project/`, `chats/`, `docs/`,
`tools/`, every `*.md` and the raw photo library at the repo root are
repo-only — `project/` is a near-duplicate of the homepage and would compete
with it in search.

Header rules live in **`vercel.json`**, which is what the host reads. `_headers`
is kept in sync only so the site stays portable to Netlify or Cloudflare;
editing it changes nothing on the live site.

`accessibility.html`, `privacy.html` and `terms.html` are **drafts**. All
three carry a visible banner saying so and contain `[להשלים]` markers for the
business name, accessibility officer, email and retention period. Have a lawyer
review them. All three are `noindex, follow` and deliberately absent from
`sitemap.xml`.

Icons are generated, not hand-made: `node tools/make-icons.mjs` rebuilds
`favicon.ico` and `assets/img/icon-*.png` + `apple-touch-icon.png` from
`assets/img/logo.jpg`. That master is only 150×150, so 180 and 192 are
upscaled — replace it with a ≥512px file and re-run when the studio has one.

## The 3D viewer

`camera-3d.html` renders a rangefinder camera built from ~35 named three.js
meshes, with orbit controls and OBJ/GLB export. The homepage embeds it via
`camera-3d.html?embed=1`, which hides the page chrome and lets the stage fill
the frame.

three.js is **vendored** into `assets/vendor/three/` and resolved through a
local import map — no CDN at runtime. If WebGL is unavailable the stage falls
back to `assets/img/camera-still.jpg` via its `fallback` attribute, so the
section still looks deliberate instead of showing an English stack trace. The
OBJ/GLB toolbar is hidden in the embedded strip and kept on the standalone page.

Model units are real-world metres, y-up, resting on `y = 0`. The stage ships no
environment map, so materials cap `metalness` around 0.3–0.4 and carry the metal
look through base colour instead.

## Configuration

The prototype's three editor props survive as `CONFIG` at the top of
`assets/js/main.js`:

| Key | Default | Effect |
| --- | --- | --- |
| `accent` | `null` | Overrides `--champagne` (and `--line` at 30% alpha) |
| `showFilm` | `true` | `false` removes the showreel section |
| `reveal` | `true` | `false` disables the scroll-in animation |
| `supabaseUrl` / `supabaseKey` | set | Where the lead form delivers |
| `formEndpoint` / `formKey` | `''` | Fallback for a generic form service |
| `whatsapp` | `972503662699` | Used by every WhatsApp link and by the form's fallback |

`assets/js/assistant.js` and `assets/js/admin.js` each carry their own `CONFIG`
at the top. The assistant's `remoteEnabled` is `false`: it answers from a
scripted knowledge base built out of what `index.html` already says, and the
optional Claude-backed tier stays off until an Edge Function is deployed.

The full palette lives in `:root` in `styles.css`.
